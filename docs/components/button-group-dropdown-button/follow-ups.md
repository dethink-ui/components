# ButtonGroup And DropdownButton Follow-Ups

These are separate product opportunities, not hidden scope in ButtonGroup or
DropdownButton.

## ResponsiveActionGroup

Only consider an automatic overflow primitive after product evidence defines
action priority, permission changes, localization growth, focus continuity,
server rendering, and behavior when actions no longer fit. Any proposal needs a
new PRD. ButtonGroup must not gain ResizeObserver measurement, child ranking,
implicit hiding, or overflow state as an implementation shortcut.

## Toolbar

A Toolbar requires an explicit command-surface contract, orientation-aware
roving focus, keyboard navigation, disabled-item behavior, and overflow rules.
It should be a separate semantic primitive rather than a ButtonGroup mode.

## ToggleGroup

A ToggleGroup owns pressed selection, value state, and single/multiple
selection semantics. It should remain separate from ButtonGroup's independent
native actions.

## Product Evidence To Collect

- real narrow-header and localization failures;
- action counts and stable priority rules across permissions;
- whether overflowed actions need discovery or status indicators;
- focus and announcement expectations when layout changes while focused;
- whether a Toolbar, application-owned handoff, or automatic overflow solves
  the observed workflow most directly.
