Use case: ui-mockup.
Create one realistic, production-quality redesign concept for the Dethink Components public documentation and showcase website. Direction name: WORKBENCH — try a component, understand its states, and take the code without jumping between disconnected sections.
Target dimensions: 1440 x 1024 desktop web interface, landscape, ONE focused primary screen. The screenshot is a proposed Button component detail view in the overhauled site. This direction makes the live explorer the heart of the site. No collage, no multiple alternatives, no device or browser chrome.
Attached references: current Dethink Button page, its expanded source view, and the component catalog. Preserve the Dethink mark, actual Button states and open-code library context. Substantially improve hierarchy and make the preview-to-copy journey immediate. Current date anchor 2026-09-19; library has 67 components and 19 recipes. No login, personal projects, AI assistant, deployment features, pricing, analytics, or invented services.
Art direction: refined technical instrument, extremely usable. Dark ink top bar and navigation rail, soft near-white spacious preview canvas, cool stone side panels, bright but restrained mint-teal accent, dark ink code panel. Sharp contrast and readable typography, precise 8px rhythm, 14–16px UI labels. Space Grotesk-like headings and Inter-like UI; code uses a simple monospace treatment. Thin dividers, subtle 6–8px corners, almost no shadows. Do not enclose the entire app inside a rounded floating card.
Top bar: Dethink/Components wordmark at left, Components active, Recipes, Guides. A single compact global search "Find anything…  ⌘ K", theme icon, GitHub icon at right.
Left sidebar 208px: search/filter component input, labelled categories Actions and Forms, under Actions Button selected with a mint line, Icon Button, Button Group; under Forms Input, Select, Checkbox, Switch. Small "All components →" link. Keep the list short and clearly scrollable.
Content heading row: breadcrumb "Components / Actions", H1 "Button", short sentence "A clear action, in every state." Main action at far right "Copy install command".
Below that: a clean local tab row "Playground" selected, "Examples", "API", "Accessibility". Do not repeat the existing component dropdown and previous/next arrows.
Main area: two-column workstation with a broad center preview and a 320px right inspector. A thin toolbar across the preview has "Live preview" plus light/dark mini control and reset. The main preview shows one large teal "Continue →" Button beautifully centered with lots of space. Beneath it, small labelled state examples "Default", "Loading", "Disabled" on one horizontal line with their actual visual buttons. Make active and disabled states unambiguous.
Right inspector labelled "Customize": only Variant segmented choice Solid / Outline / Ghost, Size choice Small / Medium / Large, a text field Label with Continue, a Right icon switch and Loading switch. Keep clear labels, clean spacing and a quiet "Reset" text action. No endless property editor.
Immediately below the preview and inspector, one full-width dark code strip labelled "Usage" and a clear "Copy code" button. Show only a short readable illustrative JSX snippet using the real public API: <Button variant="solid" size="md" rightIcon={<ArrowRight />}>Continue</Button>. Below it an install line "npx shadcn@latest add @dethink/button". Source content must not be a massive scroll wall.
One supporting section at the bottom on the base surface: "See it in a real interface" with two compact horizontal links and small actual UI thumbnails: Relay research landing and Onboarding workspace. Avoid excess badges and nested cards.
Use spacing, grouping and typography first; controls are purposeful and focus on one clear task. This is a public library website, not a design-editor SaaS. The word WORKBENCH may appear only as a tiny lower-right concept stamp; no numeric option label.
